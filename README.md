# KAIKEI smooth（会計スムーズApp）

ソフトウェア工学（水）7・8限 チーム04。アプリの表示名は「KAIKEI smooth」。決済アプリ・ポイントアプリをワンタップで呼び出し、ポイントの残高と有効期限を管理するスマートフォン向けWebアプリです。要件定義書ver.3・基本設計書Ver.2・詳細設計書に沿って実装しています。

## 動かし方

- XAMPPで確認：Apacheを起動して `http://localhost/KAIKEI%20smooth2/` を開く。
  - スマホから確認する時は、パソコンのIPアドレスで開く（例：`http://192.168.0.10/KAIKEI%20smooth2/`）。
- PHPなしで確認：`python3 -m http.server 8000` など（PHPは不要）。
  - `index.html` をダブルクリックして開く（file://）と Service Worker は動きません。
- スマートフォン実機で確認：GitHub Pages などHTTPSで公開して開く。Service Worker（オフライン動作）はHTTPSでないと動きません。
- 初めて開くとデータ引継ぎの注意が出ます。ホーム画面の「サンプルデータで試す」で、アプリ4つ・ポイント4つ・お店1つのサンプルが入ります。

## アプリの登録と起動のしくみ

- **一覧から選ぶ**：決済・交通系・ポイントなど133件から、名前で検索したりカテゴリで絞り込んだりして登録できます。端末で使えないアプリ（iPhoneでのモバイルICOCAなど）は表示しません。
- **まとめて追加**：アプリ追加画面の「まとめて選ぶ」を押すと、一覧のアプリをタップで複数選び、「選んだ〇件を追加」でまとめて登録できます。「表示中をすべて選ぶ」で、検索・カテゴリで絞り込んだアプリを一度に選べます（apps.js `setMultiMode()`・`addPicked()`）。
- **起動方法を更新**：設定画面の「↻ 起動方法を更新」は、自分で追加したアプリにURLスキームを設定した時の不具合対策です（URLスキームで開けず、ストアが開くようになったアプリを、もう一度URLスキームで試せるようにする）。説明は横の ⓘ をタップすると出ます（app.js `initTip()`）。
- **ホーム画面のアイコン**：右上の「⚙ 設定」で、ホーム画面に追加した時のアイコンを10種類から選べます（先頭の「コネクトハブ」が標準）。選んだアイコンはこの端末だけに保存されます（バックアップの対象外）。iPhoneは `apple-touch-icon`、Androidはアイコンごとのマニフェスト（`manifests/icon-XX.json`。標準は `manifest.json`）に差し替えるしくみです。ホーム画面のアイコンは追加した時に決まるため、追加済みの場合は削除してから追加し直すと変わります（js/icon.js）。候補を減らす時は `js/icon-choices.js` から消し、`index.html` の `<head>` 内のIDの並びも合わせます。
- **データのリセット**：設定画面のいちばん下の「データをリセット」で、登録したアプリ・起動履歴・ポイント・お店をすべて消します。消える件数の確認と「本当にリセットしてよろしいですか？」の2回の確認があります（apps.js `resetAllData()`）。
- **一覧にないアプリ**：App Store／Google Playの「共有」でコピーしたリンクを貼り付けるだけで登録できます。URLスキームは「詳しい設定」で任意入力です。
- **試しに起動**：登録する前に、そのアプリが開けるかを確かめられます（起動履歴には記録しません）。
- **起動のしかた**（home.js `openApp()`。詳しくは `docs/launch-design.md`）

| | URLスキームあり | URLスキームなし |
| --- | --- | --- |
| iPhone | 直接起動。失敗したら「App Storeで開く」ボタンを表示 | App Storeアプリ（`itms-apps://`）でアプリのページを開く →「開く」 |
| Android | intent URLで直接起動。失敗したらChromeが自動でGoogle Playを開く | Google Playアプリ（intent・`scheme=market`）でアプリのページを開く →「開く」 |

URLスキームは、`scheme-test.html` でのテスト結果（2026年10月30日。`docs/scheme-test-result-20261030.txt`）で決めています。**開けた（○）27件（＋手で追加した2件）はそのURLスキームで起動し、開けなかった（×）81件と、URLスキームなしで追加した23件はすべてストアのアプリのページを開きます**（詳しくは `docs/launch-design.md`）。登録済みのアプリは、新しい版を初めて開いた時に自動でこの内容に置き換わります。登録済みのアプリのURLスキームは、アプリ管理画面の ✎ から書き換えられます。

- **登録したアプリの画面**：あいうえお順（漢字で始まる一覧のアプリは読み方で並べる）→ ABC順 → その他（数字・記号で始まるもの）の順に並びます（apps.js `sortAppsByName()`）。✎ または名前をタップすると「アプリを編集」画面が開き、上から アプリ名 → ジャンル（入っているジャンルをタグで表示。タップで入れる・外す、「＋ ほかのジャンルにも入れる」で追加）→ URLスキーム を変えられます（apps.js `renderAppEdit()`・genres.js `setAppGenres()`）。
- **起動方法を更新・データをリセット**：右上の「⚙ 設定」のいちばん下（「アプリの起動・データ」）にあります。
- **ジャンル**：最初のジャンルは29種類で、1つのジャンルは8件まで、1つのアプリは1つのジャンルだけに入ります（重複なし。`tools/apps_data.py` の `CATEGORIES`。`build_presets.py` が8件を超えるとエラーにします）。一覧にないアプリは「その他」。
  - アプリ追加画面のジャンルのタグの最後の「✎ ジャンルを編集」、アプリ管理画面の「🏷 ジャンルを編集」、アプリを編集画面の「ジャンルを作る・編集する」から（ホーム画面には編集機能を置かない）、ジャンルを作る・名前を変える・入れるアプリを変える・タグに出さない（最初のジャンルのみ）・削除（自分で作ったジャンルのみ）ができます。変えたジャンルでは、1つのアプリを複数のジャンルに入れられます（重複あり）。
  - 変更は localStorage の `genreSettings` に保存し、バックアップにも含めます（読み込んで合わせる時は、最後に変えた方の内容が残ります）。「データをリセット」で最初の状態に戻ります。
- **ホームの段落**：ジャンルが「すべて」で検索していない時は、★お気に入り → 24時間以内 → 3日以内 → 1週間以内 → 1か月以内 → 1か月以上使っていない、の段落に分けて表示します（上の段落に入ったアプリは下には出さない。空の段落は出さない。段落の中はよく使う順。home.js `renderAppGroups()`）。
- **店舗の検索**：店舗画面の上の検索欄で、お店の名前や、そのお店に紐付けたアプリの名前・読み方（ひらがな）で探せます（お店が1件以上ある時だけ表示。shops.js `renderShops()`）。
- **ホームの検索・ジャンル**：ホーム画面のアプリの並びの上にある検索欄で、登録したアプリを名前・読み方（ひらがな）で探せます。その下のジャンルのタグで絞り込めます（登録したアプリにあるジャンルだけを表示。一覧にないアプリは「その他」）。home.js `renderHomeGrid()`。
- **アプリの名前**：アプリ管理画面で名前をタップすると、一覧から追加したアプリも好きな名前に変えられます（30文字まで。一覧のアプリは「元の名前」の候補ボタンで戻せる）。文字のアイコンも新しい名前の1文字目になります。
- **アイコンの画像**：アプリ管理画面でアイコンをタップすると、写真やファイルから好きな画像を選べます（中央を正方形に切り抜いて96px四方に縮小して保存。もう一度タップで「選び直す」「元に戻す」）。
- **検索**：アプリ追加画面の検索は、アプリ名のほか読み方（ひらがな）でも探せます（「すいか」→Suica、「すたば」→スターバックス）。読み方は `tools/apps_data.py` の `READINGS`。

### URLスキームのテスト

スマホで `scheme-test.html` を開くと、全アプリの候補を1つずつタップして試し、○×を記録できます。「結果をコピー」で結果をテキストにして共有できます。

### 対応アプリを追加・修正するには

1. `tools/apps_data.py` に1行追加する（App Storeのアプリ番号・Google Playのパッケージ名・URLスキーム）
2. `python3 tools/build_presets.py` を実行する（js/presets.js と docs/app-list.* が作り直されます）
3. `sw.js` の `CACHE_NAME` の版数を上げる

## ログ出力（運用担当者からの変更要求）

障害の原因調査と利用状況の分析のため、利用者の操作とシステム内部の主な処理の結果をログに記録します（`js/log.js`）。

### チームで統一するきまり

- **レベル**：2つだけ。
  - `INFO`：各機能が正常に処理を完了した時
  - `ERROR`：処理中に異常が起きた時（保存できない、データが壊れている、起動できない、想定外のエラーなど）
  - 入力ミス（必須欄が空など）は異常ではないので記録しない。
- **書き方**：各機能の担当者は、次の2つだけを使う。
  - `logInfo('機能ID', 'メッセージ', { 詳細 })`
  - `logError('機能ID', 'メッセージ', エラー, { 詳細 })`（エラーには catch した Error を渡す。なければ `null`）
  - メッセージは「〇〇した」「〇〇できなかった」の形にそろえる。
  - メモ・パスワードなど個人的な内容は書かない。書くのはID・名前・件数くらいにする。
- **形式**：1件を1行にする。
  - `日時 レベル [機能ID 機能名] メッセージ 詳細(key=value) #セッション`
  - 例：`2026-11-11 16:05:12.345 INFO  [F07 ポイント情報管理] ポイントを追加した id=m3k9x2 name=楽天ポイント #a1b2`
  - セッションは、ページを開くたびに変わる4文字。同じ回の操作をまとめて追うのに使う。
- **機能名**：`js/log.js` の `LOG_FUNCS` で統一する。ここにない機能IDは使わない（増やす時はここに追加する）。

| 機能ID | 機能名 | 主なログ |
| --- | --- | --- |
| F01 | ホーム表示 | ホームを表示した |
| F02 | アプリ登録 | アプリを登録した（一覧から・手入力・まとめて・全部・サンプル）、試しに起動した |
| F03 | アプリ起動 | 起動を始めた、開いた、ストアを開いた／ERROR：直接開けなかった、起動方法がない |
| F04 | 起動履歴記録 | 起動履歴を記録した、古い履歴を削除した |
| F05 | 並び替え | 登録したアプリを並び替えた |
| F06 | アプリ管理 | お気に入り、名前・URLスキームの保存、アイコン画像、削除 |
| F07 | ポイント情報管理 | ポイントを追加・更新・削除した |
| F08 | 有効期限お知らせ | 有効期限が近いポイントを判定した（件数） |
| F09 | オフライン動作 | Service Workerを登録した／ERROR：登録できなかった |
| F10 | 初回注意表示 | 初回の注意を表示した |
| F11 | 店舗ショートカット | お店を追加・更新・削除した、お店のアプリを表示した |
| X01 | ジャンル | ジャンルを作った・更新・削除・最初に戻した、アプリの入るジャンルを変えた |
| X02 | データ移行 | バックアップを保存・コピー・読み込んだ／ERROR：読み込めなかった |
| X03 | ホーム画面アイコン | ホーム画面のアイコンを変えた |
| X04 | データリセット | データをリセットした |
| SYS | システム共通 | アプリを開いた、画面を表示した、データを読み書きできなかった、想定外のエラー（`window.onerror`・`unhandledrejection`） |

- **保存先**：この端末のブラウザの localStorage のキー `appLog`。DB・サーバーには保存しない。
  - 新しい方から1000件を残し、古いものから消す。
  - ブラウザの開発者ツールのコンソールにも同じ1行を出す。
  - ログはバックアップの対象外で、「データをリセット」でも消えない。
- **見方**：右上の「⚙ 設定」の「ログ（運用担当者向け）」から使う。
  - 件数とERRORの件数、最近の30件を表示する。
  - 「ログを保存」で `kaikei-smooth-log-日付.log`（テキスト）に書き出し、「ログを消す」で消す。

## データ（詳細設計書 7.1）

localStorage に次のキーで保存します。サーバーには送信しません。

- `apps`：id, name, url（URLスキーム・任意）, schemeCandidates（起動方法の候補）, launch（端末の種類ごとの試した結果）, iosAppId, androidPackage, presetId, icon, iconImage（利用者が設定したアイコン画像。96px四方のdata URL・任意）, favorite, createdAt
- `launchHistory`：id, appId, launchedAt（30日より古いものは起動時に削除）
- `points`：id, name, amount, expiry, notifyDays, memo
- `shops`：id, name, appIds
- `noticeShown`：初回の注意を表示したか（true／false）
- `appLog`：ログ（上の「ログ出力」。最大1000件）
- `syncTombstones`：削除した記録のIDと時刻（バックアップを合わせて読み込んだ時に復活しないようにする）
- `apps`・`points`・`shops` の各記録には `updatedAt`（最後に変わった時刻）が自動で付きます

データを消して最初からやり直すには、ブラウザの開発者ツールで localStorage を削除してください。

## 実装で決めたこと（詳細設計書 10.3 の未決定事項）

チームで確認し、変える場合は該当箇所を直してください。

| 項目 | 今の実装 | 場所 |
| --- | --- | --- |
| 同じプリセットの二重登録 | できない（「登録済み」と表示） | apps.js `renderAppAdd()`・`addPreset()` |
| 起動に失敗した時の履歴 | 記録する（タップした時点で記録） | home.js `launchApp()` |
| 失効済みポイントのホーム表示 | 出さない（ポイント一覧で「失効済み」と表示） | points.js `getAlerts()` |
| https: のURLを登録した場合 | 別画面で開き、起動判定はしない | home.js `launchApp()` |

## 必ず実機で確認すること

- iPhone：`itms-apps://` でApp Storeアプリが開くか（Safari・ホーム画面に追加した状態の両方）。
- URLスキームの候補（`scheme-test.html` で確認）
- Android：Google Playアプリのアプリページが開くか。PayPalのintent URLで直接起動し、未インストール時にGoogle Playへ切り替わるか。
- 起動失敗の判定時間（home.js の `LAUNCH_WAIT_MS`、2.5秒）は、OSの確認ダイアログが出る端末で誤判定しないか確認してください。
- オフライン：一度開いた後に機内モードにして、アプリが起動し、一覧とポイントが見られること。
- ファイルを更新したら `sw.js` の `CACHE_NAME` の版数（今は v21）を上げてください。上げないと古い画面が表示され続けます。
